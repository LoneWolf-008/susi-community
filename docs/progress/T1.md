# T1 — Baseline DB, migrasi, dan seed

**Branch:** `implement/T1-db-baseline-seed` · **Status:** selesai

## Yang dikerjakan

1. **`backend/db/schema.sql`** dari dump `susi_community.sql`:
   - tanpa `DEFINER`, tanpa tabel stand-in `v_*`, tanpa header/footer phpMyAdmin;
   - `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci` di semua tabel. Di
     `susi_community_db` (salinan dump di MySQL lokal), dua tabel tanpa ENGINE ternyata
     mendapat `utf8mb4_0900_ai_ci` sementara tabel lain `utf8mb4_unicode_ci`;
   - indeks/FK ditulis inline, tipe tanpa display width, `CURRENT_TIMESTAMP` tanpa kurung;
   - `audit_logs.meta` tetap `LONGTEXT + CHECK (json_valid(meta))` (bukan tipe `JSON`) agar
     MySQL dan MariaDB sama-sama mengembalikan string ke `mysql2`;
   - `sp_verify_project` dipertahankan (tanpa DEFINER) karena controller masih memakainya;
     dihapus lewat migrasi di T2.
2. **Runner migrasi** `utils/migrate.js` + `utils/sqlSplit.js`. Script: `db:init`, `db:migrate`,
   `db:status`, `db:reset` (non-production). Detail di README bagian Database.
3. **Seed** `utils/seed.js` + `db/seeds/demo.js` + `db/seeds/kb.json`: idempoten, satu transaksi,
   ditolak di production tanpa `--force`. Akun admin dari `ADMIN_EMAIL`/`ADMIN_PASSWORD`, akun
   demo lain dari `SEED_USER_PASSWORD`.
4. **Konsistensi reputasi:** `utils/reputation.js` berisi ambang level satu-satunya
   (`<20` Muda, `<50` Terpercaya, `≥50` Ahli) dan `recomputeReputation()` yang menyamakan
   `talent_profiles` dengan `SUM(reputation_events.delta)`. T2 memakai modul yang sama.
5. **README:** tabel perintah database dan akun demo.

## Keputusan yang diambil

| Keputusan | Alasan |
|---|---|
| Rekonstruksi dua CHECK (`chk_mod_reject_reason`, `chk_pd_content`) | Dump mencetak kedua tabel tanpa ENGINE, pola phpMyAdmin saat ada CHECK tingkat tabel. DDL asli tidak ditemukan di folder proyek mana pun. Isi CHECK mengikuti aturan yang sudah ditegakkan controller. |
| `db:init` menolak DB berisi tabel tanpa `schema_migrations` | Lebih aman daripada menebak versi skema DB hasil impor dump. Dump tidak berisi data, jadi `db:reset` tidak membuang apa pun yang berharga. |
| `db:reset` menghapus tabel, bukan `DROP DATABASE` | Bekerja juga di hosting yang tidak memberi hak `CREATE DATABASE`. |
| Persona seed = seed SDD §2.5 | Konsisten dengan proposal/SDD; teks kebutuhan bukan karangan baru. |
| 14 kebutuhan (bukan ±10) | Agar semua status T1 tercakup sekaligus menyisakan kebutuhan `OPEN` dengan/tanpa pelamar untuk kedua jalur (dipakai T3, T6–T8). |
| Proyek dari kebutuhan liaison: `projects.requester_id = liaison` | Keputusan desain #1 (pemilik proksi) sudah diterapkan di data agar T3 tinggal menyesuaikan kode. |
| KB awal = 11 entri gabungan FE, isi tidak diubah | Larangan mengarang isi KB. Penambahan KB bersumber dokumen ada di T12. |
