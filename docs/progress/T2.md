## Temuan tambahan yang ikut diperbaiki

1. **Melamar kebutuhan jalur Assisted → 500.** Notifikasi dikirim ke `need.requester_id` yang
   `NULL`. Sekarang ke pemilik efektif (liaison). Cakupan penuh pemilik proksi tetap di T3.1.
2. **Refresh token kembar.** Dua refresh token untuk user yang sama di detik yang sama identik
   (payload sama), sehingga `rotateRefreshToken` bisa 500 di `uq_rt_hash`. Ditambah `jwtid` acak.
   JWT juga dikunci ke HS256.
3. **`members_count - 1` pada kolom UNSIGNED** memicu error saat nilainya 0 (keluar komunitas).
4. **`updateVisit` bisa mengubah `status` bebas** (melompati start/finish, nilai enum tidak valid
   → 500). Kini status hanya lewat `/start` dan `/finish`.
5. **`GET /needs/:id`** menampilkan kebutuhan `PENDING`/`REJECTED` milik siapa pun ke semua
   pengguna login. Kini hanya pemilik dan admin.
6. **`openDispute`** bisa dibuka di status apa pun (termasuk `COMPLETED`). Kini hanya
   `IN_PROGRESS`, `AWAITING_VERIFICATION`, `REVISION`.
7. **`requestRevision`** kini mengosongkan `talent_marked_done_at` agar sign-off dua arah tetap
   berlaku setelah revisi.
8. **Dependensi:** `npm audit fix` (express 4.22.3), `bcrypt@6` (menghapus `tar` kritis lewat
   `node-pre-gyp`; hash lama tetap cocok, sudah diuji login seed), `nodemon` diganti
   `node --watch`. Hasil `npm audit`: **0 kerentanan**.

## Perubahan bentuk API (penting untuk T4–T10)

- Semua endpoint daftar kini mengembalikan `data: { items, total, page, limit }` (sebelumnya
  array mentah): `needs/mine`, `projects/mine`, `applications/mine`, `applications/for-need/:id`,
  `communities`, `discussions`, `liaison/visits`, `notifications`, `talent/top`,
  `talent/:id/testimonials`, `testimonials/mine`, `testimonials/public/:id`, dan seluruh daftar admin.
- `GET /communities` menambah kolom `is_member` dan filter `?mine=true`.
- `GET /needs/mine` menambah `applicants`, `project_id`, `project_status`.
- Beberapa status 400 untuk transisi tidak sah berubah menjadi **409** (agree, deliveries, revisions).
- `DELETE /needs/:id` tidak lagi menghapus baris; respons `{ id, status: 'CLOSED' }`.

## Belum beres / dicatat untuk task lain

- **Peran liaison** belum diizinkan di route `for-need`, `decide`, `verify`, `revisions` (T3.1).
  Logika kepemilikan di service dan controller sudah memakai pemilik efektif, jadi T3 tinggal
  membuka route-nya.
- **Pihak proyek belum bisa membaca pesan admin di sengketa** (`getDisputeById` khusus admin).
  Diusulkan `GET /api/projects/:id/dispute` di T3.7 bersama endpoint pernyataan.
- **Validasi input** masih manual di beberapa endpoint (mis. `communities.create` menerima `type`
  bebas → error enum = 500, `updateMe` tanpa cek tipe). Ditutup oleh zod di T3.6.
- **Mimetype tetap klaim klien.** Pemeriksaan magic bytes (mis. paket `file-type`) belum dibuat;
  risiko rendah karena berkas hanya bisa diunduh pihak proyek dengan `Content-Disposition: attachment`.
- **Berkas yang diunggah tetapi tidak pernah dikirim** tetap di disk sampai ada job pembersih
  (mis. hapus yang > 24 jam dan tidak tercatat). Belum dibuat.
- Rate limit memakai memory store: reset saat server restart dan tidak dibagi antar-instance.
  Cukup untuk demo satu instance.
